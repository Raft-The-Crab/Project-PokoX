# 33 — PokoX Signature Differentiators

## Purpose

This document proposes a coherent set of product advantages that can make PokoX recognizably different from Roblox. No individual feature is claimed to be globally unique. The differentiation comes from PokoX's combination, implementation quality, policies and consistent experience.

The goal is not to copy another platform's feature checklist. PokoX should build a distinct identity around creator control, transparent operations, approachable creation, offline capability, player trust and a colourful community.

## Product pillars

### 1. Play-first, offline-capable platform

- Make offline play a first-class mode for games whose creators enable it.
- Let a player launch eligible downloaded games without signing in where licensing and game design permit.
- Keep local saves available offline and synchronize later with conflict handling.
- Clearly label online-only, offline-capable, player-hosted and dedicated-server games.
- Let creators specify which features require an account or network connection.
- Do not pretend an offline result has the same anti-cheat assurance as a server-validated online result.

**Signature experience:** a player can open their library, see what works offline, and launch a compatible game without a platform connection.

### 2. Creator-owned hosting choice

- Support offline, player-hosted and developer-hosted dedicated modes according to game capability.
- Provide one shared server runtime, diagnostics and documented package contract.
- Make server requirements, supported runtime version, region/latency evidence where measured, and last heartbeat visible.
- Provide a self-hosting quick-start and reproducible server package validation.
- Do not promise global hosting or uptime that PokoX does not operate.
- Clearly distinguish PokoX-operated official game servers from third-party developer hosting.

**Signature experience:** creators can choose where to run their games instead of assuming PokoX supplies every server.

### 3. A readable, inspectable creation stack

- MUTE is designed to be approachable, documented and sandboxed.
- Provide an event inspector, debugger, profiler, network inspector and runtime logs in Studio.
- Make script permissions and capabilities visible before publishing.
- Provide a local test server and deterministic test fixtures where feasible.
- Explain why a script or package failed validation in useful language.
- Offer a beginner mode with guided templates and an advanced mode with full controls.

**Signature experience:** Studio teaches creators what their game is doing instead of hiding errors behind generic messages.

### 4. Publishing with actionable human review

- Every game update goes through the required review workflow.
- Human moderators make final approval decisions.
- Give developers specific findings, affected locations and reproduction steps when a submission fails.
- Keep the previous approved release available during normal review, subject to emergency safety suspension.
- Provide a secure Review Runtime and inspector so moderators can test actual game behavior.
- Keep a clear review history and one appeal opportunity under the confirmed policy.
- Track the four formal review attempts exactly as the owner-defined policy is finalized; platform-caused infrastructure failures must not consume an attempt.

**Signature experience:** creators receive useful, reproducible feedback rather than an unexplained rejection.

### 5. Community built into the game platform

- Poko Community is native to PokoX and shares the same identity, safety controls, notifications and discovery.
- Connect game pages to developer posts, known issues, events, update notes and Q&A.
- Let creators host playtests, recruit collaborators and gather structured feedback.
- Keep social groups separate from Studio project permissions.
- Provide a community roadmap with transparent status and explanations.
- Add Help PokoX contributions without granting donors or volunteers inappropriate privileges.

**Signature experience:** the community is where players and creators help games improve, not a detached social network.

### 6. Transparent game information

Every game can have a structured **Poko Game Passport** containing:
- Content suitability labels and plain-language explanations.
- Supported modes: offline, player-hosted, dedicated server.
- Input and accessibility support.
- Approximate download size and supported device classes.
- Required permissions/capabilities.
- Whether chat, voice, analytics, cloud saves or purchases are used.
- Last updated date and current release version.
- Hosting responsibility and server status evidence, when available.
- Known issues and developer support links.
- Monetization disclosures.

Only display measured or verified claims as verified. Developer-provided disclosures must be marked as such until checked.

### 7. Player-respecting discovery

- Give users useful filters: genre, input, device, offline support, server mode, accessibility, content labels and session length.
- Explain why a game appears in a recommendation.
- Provide controls to tune recommendations, clear history and opt out of personalization where feasible.
- Include curated collections and chronological views alongside algorithmic discovery.
- Avoid ranking games solely by raw playtime or engagement.
- Detect review manipulation and incentivized engagement.
- Do not let developers buy undisclosed organic ranking.

**Signature experience:** players can find games based on what they actually want to play, not only what maximizes time spent.

### 8. A meaningful achievement system

- Every game begins with 100 achievement slots.
- Unlimited permanent expansions: each purchase adds 10 slots to one game for 150 Pokoins.
- Capacity is attached to the game and cannot be transferred.
- Support hidden achievements, categories, collections, version history and validation.
- Platform achievements celebrate positive creation and community contributions.
- Avoid achievements for mass invites, report volume, spending or moderation punishments.

**Signature experience:** achievements are a durable game identity and player collection, with transparent creator-controlled capacity.

### 9. Player data and portability

- Provide account data export in a documented format where feasible.
- Provide account deletion and privacy controls with clear explanations of retained records required for safety, fraud prevention or law.
- Keep project files in a documented `.pk` format with versioned manifests.
- Provide creators with source/project backups and release history.
- Provide clear asset licenses and dependency manifests.
- Do not imply that platform account identity, purchased entitlements or protected third-party assets are freely transferable.

**Signature experience:** creators can back up their work and understand what they own, what is licensed and what is platform-bound.

### 10. Performance and compatibility transparency

- Publish minimum/recommended device requirements for the client and Studio.
- Show game download size and tested compatibility information.
- Give developers performance budgets and profiling tools.
- Record runtime compatibility requirements in package manifests.
- Warn about outdated server runtimes and incompatible assets.
- Publish incident and service status updates when platform services are affected.

**Signature experience:** players and creators can understand performance and compatibility before they encounter problems.

## Additional signature programmes

- **Poko Labs:** opt-in experimental features with clear labels, feedback controls and rollback.
- **Creator Playtest Rooms:** invite-only test sessions with feedback forms, bug capture and version identification.
- **Poko Game Jams:** recurring themed creation events with transparent judging criteria.
- **Starter Game Kits:** small, inspectable sample projects for Obby, block-building, multiplayer and UI.
- **MUTE Learning Path:** interactive lessons with safe exercises and test sandboxes.
- **Community Knowledge Base:** accepted answers and versioned tutorials maintained by contributors and reviewed by staff.
- **Creator Reliability Cards:** display verified release/update history and server health evidence without pretending a score guarantees quality.
- **Accessibility Profiles:** reusable input, text, colour, audio and motion preferences exposed to games through permissioned APIs.

## Principles that protect differentiation

- Do not compete by adding every feature at once.
- Do not make Pokoins necessary for basic play, safety or creator access.
- Do not sell moderation influence, discovery rank or safety exceptions.
- Do not claim a feature is unique unless verified; compete through execution and consistency.
- Do not sacrifice child safety or privacy to increase engagement.
- Do not make unsupported uptime, anti-cheat, performance or ownership promises.
