# 37 — Differentiator Roadmap and Priorities

## Prioritization rule

PokoX should not attempt to launch every differentiator at once. Prioritize features that create a reliable core loop, build trust and are affordable to operate.

## Priority 0 — Required foundations

- Reliable player client, Studio and runtime.
- Stable game package and project formats.
- Secure identity and permission model.
- Offline launch path for games that support it.
- Server-authoritative online gameplay primitives.
- Human moderation and isolated Review Runtime.
- Game Passport data model.
- Basic integrated Community identity, profiles and safety controls.
- Achievement entitlement ledger with unlimited game-specific expansions.
- Account privacy, block/report and support workflows.
- Diagnostics, crash reporting, backups and restore tests.

## Priority 1 — Strong launch differentiators

- Offline-capable game library and clear offline labels.
- Developer-hosted dedicated server workflow with validation tools.
- Actionable moderation findings tied to a specific package hash.
- Game Passport with content, network, device and monetization disclosures.
- Player-respecting discovery filters and non-personalized browsing.
- Studio beginner mode, starter templates and one-click local testing.
- Achievement collection and permanent per-game capacity expansion.
- Integrated community posts, groups, Q&A and game announcements.
- Creator release history and rollback where safe.

## Priority 2 — Growth features

- Creator Playtest Rooms.
- Game jams and community challenges.
- Collaboration board and skill profiles.
- MUTE interactive learning path.
- Project export and dependency/license report.
- Accessibility profiles and game accessibility disclosures.
- Poko Labs opt-in experiments.
- Community roadmap proposals and voting.
- Aggregated creator analytics.
- Creator reliability cards based on verified measurements.

## Priority 3 — Only after operational maturity

- Large public asset marketplace.
- Advanced recommendation personalization.
- Live collaborative editing.
- More extensive cross-device save synchronization.
- Additional server hosting integrations.
- Expanded creator monetization.
- Advanced automated test generation.
- Community-funded infrastructure at meaningful scale.

## What PokoX should avoid

- Copying Roblox UI, terminology, branding or proprietary systems.
- Promising to be cheat-proof or impossible to reverse engineer.
- Launching a large marketplace before licensing, payments, refunds and moderation are ready.
- Turning community contributions into paid moderation influence.
- Rewarding spam, idle farming, mass invites or report volume.
- Showing misleading uptime or performance scores.
- Over-personalizing discovery without user controls.
- Requiring always-online authentication for games explicitly designed to work offline.
- Shipping untrusted game code with unrestricted native or operating-system access.

## Differentiation scorecard

Review quarterly:
- Percentage of eligible games that launch offline successfully.
- Percentage of creator submissions with actionable review feedback.
- Time from a creator finding an error to reproducing it.
- Number of games with complete Game Passports.
- Player use of meaningful discovery filters.
- Creator success rate from starter project to first playable build.
- Playtest feedback usefulness and bug reproduction rate.
- Server package validation success rate.
- Accessibility feature coverage.
- Safety report response quality and appeal outcomes.
- Infrastructure cost per active player and per game session.

Do not optimize a single metric at the expense of player wellbeing, safety, creator fairness or service reliability.
