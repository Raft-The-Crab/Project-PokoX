# 09 — Marketplace and Asset Ecosystem

## Marketplace categories
- Models and props.
- Materials and textures.
- Audio and sound effects.
- Animations.
- UI components and templates.
- MUTE libraries.
- Project templates.
- Plugins/tools only if safely sandboxed and signed.

## Launch approach
Start with a curated/free asset library. Add paid listings only after creator identity, licensing, payments, refunds, moderation and fraud processes are ready.

## Asset listing requirements
Each listing should include:
- Creator/team.
- Description and screenshots.
- Supported engine/runtime version.
- File type and size.
- Dependencies.
- License and permitted uses.
- Version history.
- Content labels if applicable.
- Whether modification and redistribution are allowed.

## Security and quality
- Scan uploaded archives.
- Verify file signatures and hashes.
- Reject executable native code in ordinary assets.
- Validate geometry, texture dimensions and audio duration.
- Inspect embedded metadata and external references.
- Track dependencies and known vulnerable versions.
- Allow revocation of malicious or infringing assets.
- Preserve the exact asset version used by each published game.

## Licensing
Require creators to confirm they have rights to upload and distribute their assets. Provide a takedown/contact process and a repeat-infringer policy reviewed by qualified counsel. Do not assume a public download is free to reuse.

## MUTE libraries
- Signed library packages.
- Version pinning.
- Permission declarations.
- Dependency manifests.
- Changelogs.
- Security advisories.
- Ability to revoke compromised versions.
- Avoid silently updating dependencies in published games.

## Search and reputation
Rank by relevance, compatibility, quality and trust signals. Do not let ratings alone determine visibility. Clearly label official Poko assets.
